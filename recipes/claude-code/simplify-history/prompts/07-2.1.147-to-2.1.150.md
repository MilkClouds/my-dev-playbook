# /simplify implementation #7 — the rewrite

- **Versions**: 2.1.147..2.1.150 (4 versions: 2.1.147, 2.1.148, 2.1.149, 2.1.150)
- **Command name**: `code-review`
- **Aliases**: `["simplify"]` (so `/simplify` still works but invokes this new behavior)
- **Description**: `Review the current diff for correctness bugs at the given effort level (low/medium: fewer, high-confidence findings; high→max: broader coverage, may include uncertain findings). Pass --comment to post findings as inline PR comments.`
- **Argument hint**: `[low|medium|high|xhigh|max] [--comment] [<target>]`

## What changed

This is the version where the old `/simplify` was **functionally replaced**, not just renamed. The previous 6 implementations (2.1.63..2.1.146) shared a single ~3-4 KB markdown prompt with three review agents (Reuse / Quality / Efficiency) and Phase 3 = direct fix.

2.1.147+ throws all of that out and replaces it with a **multi-piece, effort-aware, verify-then-report architecture**. The findings are NEVER auto-fixed — they're returned as a JSON array, optionally posted as PR comments.

## Prompt architecture

The prompt is no longer a single template literal. It's composed at runtime from named pieces by effort level. All pieces extracted from the 2.1.150 binary are in [`pieces-2.1.147-to-2.1.150/`](pieces-2.1.147-to-2.1.150/).

| File | What it is |
|---|---|
| [`effort-low.md`](pieces-2.1.147-to-2.1.150/effort-low.md) | Header for `low`: 1 diff pass, no verify, ≤4 findings |
| [`effort-medium.md`](pieces-2.1.147-to-2.1.150/effort-medium.md) | Header for `medium`: 3 angles × 6 candidates, 1-vote verify, ≤8 findings |
| [`effort-high.md`](pieces-2.1.147-to-2.1.150/effort-high.md) | Header for `high`/`xhigh`/`max`: 3 angles × 6 candidates, 1-vote verify (recall-biased), ≤10 findings |
| [`phase0-gather-diff.md`](pieces-2.1.147-to-2.1.150/phase0-gather-diff.md) | Run `git diff @{upstream}...HEAD` etc. to get the unified diff under review |
| [`angles-A-B-C-line-removed-cross.md`](pieces-2.1.147-to-2.1.150/angles-A-B-C-line-removed-cross.md) | Three review angles: line-by-line scan, removed-behavior audit, cross-file caller/callee trace |
| [`angles-D-E-language-wrapper.md`](pieces-2.1.147-to-2.1.150/angles-D-E-language-wrapper.md) | Two more angles (used at higher effort): language-specific pitfalls, wrapper/proxy correctness |
| [`phase2-verify-1vote-3state.md`](pieces-2.1.147-to-2.1.150/phase2-verify-1vote-3state.md) | Verify step at medium effort: CONFIRMED / PLAUSIBLE / REFUTED |
| [`phase2-verify-recall-biased.md`](pieces-2.1.147-to-2.1.150/phase2-verify-recall-biased.md) | Verify step at high effort: recall-biased variant |
| [`phase3-sweep-gaps.md`](pieces-2.1.147-to-2.1.150/phase3-sweep-gaps.md) | Final sweep for defects the first pass missed |
| [`output-json.md`](pieces-2.1.147-to-2.1.150/output-json.md) | Return findings as JSON array (file, line, summary, failure_scenario) |

## Posting to GitHub (`--comment` flag)

The only piece my main extractor caught (because it's the topmost template literal in registration order). Reproduced here for completeness:

```markdown
## Posting to GitHub (--comment)

The `--comment` flag was passed. After producing the findings list, if the
review target is a GitHub PR, post each finding as an inline PR comment via
`mcp__github_inline_comment__create_inline_comment` (one call per finding;
include a suggestion block only when it fully fixes the issue). If that tool
is not available in this session, fall back to `gh api` (repos/{owner}/{repo}/pulls/{pr}/comments)
or print the findings instead. If the target is not a PR, print the findings
to the terminal and note that `--comment` was ignored.
```

## Diff vs the old simplify (#1–#6)

| Axis | Old (2.1.63..2.1.146) | New (2.1.147+) |
|---|---|---|
| Goal | Cleanup + bug-fix (reuse / quality / efficiency) | Correctness-bug detection only |
| Output | Direct edits to the source | JSON list of findings |
| Agents | 3 parallel reviewers (Reuse / Quality / Efficiency) | Up to 5 angles + verifier + sweeper |
| Action | Auto-apply fixes | No edits; print or post as PR comments |
| Argument | Free-text "Additional Focus" (≤2.1.145) or effort level (2.1.146) | Effort level + optional `--comment` + optional target |
| Phase 3 | "Fix each issue directly" | "Sweep for gaps" — find more defects, still no fix |

This is the version that triggered the user's complaint: `/simplify` still works as an alias, but pushes through to the new behavior which never edits files.
